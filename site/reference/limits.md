# Limits, retry schedules and guarantees

This page is generated by `mix relay.docs.limits` from the API contract (`x-relay-limits`), the shipped `channel_parameters` data set and the error catalog: the same sources the server reads. Change the source, not this page.

## Guarantee

Relay provides at-least-once delivery with durable idempotency, giving effectively-once processing.

Every mutating request carries an `Idempotency-Key` of 8 to 255 characters, kept for 24 hours. A repeated request with the same key and body gets the stored response with `Idempotency-Replayed: true`. A problem document for an exceeded limit names it in `limit_name`, `limit` and `actual`.

## Retry schedules

### Webhook deliveries

The default schedule waits PT0S, PT5S, PT5M, PT30M, PT2H, PT5H, PT10H, PT14H, PT20H, PT24H before attempts 1 to 10, each wait with up to 20 % jitter. An endpoint may set its own schedule of 1 to 15 attempts spanning PT1M to P7D, each wait between PT5S and PT24H.

### Channel deliveries

From `channel_parameters` version v3. The failure classes `permanent_target`, `permanent_content`, `policy`, `sender_config` are never retried. `exponential` waits a full-jitter random time up to min(cap, base × 2^(n−1)) after the n-th failed attempt; `retry_after` waits the provider's `Retry-After`, or the default when it gives none, plus up to 20 %. An empty key field matches every value.
